# Конвенция именования Jira Version

Справочник для `/ticket-writer:release-version`. Полная логика формирования имени, включая edge cases, которые не помещаются в основной шаблон.

## Базовый формат

```
[Revenue/<Stack>]: <Product> — <PI> <Sprint> <Release> — <Краткое описание>
```

- `Stack` — `BE` (Backend) или `FE` (Frontend). Один релиз — один стек, не смешивать.
- `Product` — `Glory`, `Divine` или `Banger`. Один релиз — один продукт, не смешивать.
- `PI` — Program Increment, например `PI8`.
- `Sprint` — номер спринта внутри PI, например `S5`.
- `Release` — `R1` (mid-sprint) или `R2` (end-of-sprint). Каденция — 2 релиза на прод за спринт.
- `Краткое описание` — суть релиза, 3–10 слов, без канцеляризма (см. общие правила в [gtp-conventions.md](../shared/gtp-conventions.md)).

## Хотфиксы

```
[Revenue/<Stack>]: <Product> — <PI> <Sprint> <Release>-hotfix.<K> — <Описание>
```

`K` — порядковый номер хотфикса к конкретному релизу (`R1` или `R2`), начиная с 1.

### Хотфикс к хотфиксу

Если после `R2-hotfix.1` нужен ещё один хотфикс к тому же релизу — нумерация продолжается: `R2-hotfix.2`, `R2-hotfix.3` и т.д. Не начинать нумерацию заново и не создавать вложенные обозначения вида `hotfix.1.1`.

Пример последовательности для одного релиза:
1. `[Revenue/BE]: Glory — PI8 S5 R2 — Оптимизация gamer-score`
2. `[Revenue/BE]: Glory — PI8 S5 R2-hotfix.1 — Фикс 500-ок в exchange-rate`
3. `[Revenue/BE]: Glory — PI8 S5 R2-hotfix.2 — Фикс повторного списания баланса`

## BE и FE одного продукта в один день

Это два разных Version, даже если деплоятся в одну дату и относятся к одной фиче. Не объединять в одно имя/описание.

- `[Revenue/BE]: Glory — PI8 S5 R1 — Бонусная система`
- `[Revenue/FE]: Glory — PI8 S5 R1 — Бонусная система, новый UI кабинета`

## Два продукта в один день

Это тоже два разных Version — Glory, Divine и Banger релизятся независимо друг от друга, общего Version на несколько продуктов не бывает.

- `[Revenue/BE]: Glory — PI8 S5 R1 — Фикс конвертации валют`
- `[Revenue/BE]: Divine — PI8 S5 R1 — Фикс конвертации валют`

Если один и тот же фикс выкатывается на оба продукта — это по-прежнему два отдельных Version с одинаковым описанием фичи, но разными задачами/тегами, если стек продуктов разделён.

## Сброс нумерации R1/R2

Нумерация `R1`/`R2` привязана к спринту, а не к календарному месяцу или PI целиком. При переходе на новый спринт нумерация начинается заново:

- `PI8 S5 R1`, `PI8 S5 R2` — релизы спринта 5.
- `PI8 S6 R1`, `PI8 S6 R2` — релизы спринта 6, нумерация не продолжает предыдущий спринт.

Не путать номер релиза в спринте (`R1`/`R2`) с порядковым номером хотфикса (`hotfix.<K>`) — это независимые счётчики.
