# Конвенция именования Jira Version

Справочник для `/ticket-writer:release-version`. Полная логика формирования имени, включая edge cases, которые не помещаются в основной шаблон.

## Базовый формат

Backend:

```
[Revenue/BE]: <PI> <Sprint> <Release> — <Краткое описание>
```

Frontend:

```
[Revenue/FE]: <PI> <Sprint> <Release> — <Проект> — <Краткое описание>
```

- Бренд (`Glory` / `Divine` / `Banger`) в имени версии **не указывается** ни для BE, ни для FE.
- `Проект` — только для FE: `Админка` или `casino-web (клиент)`. Это два разных проекта с разными кодовыми базами и разными релизами, даже если катятся в один день.
- Стек в префиксе — `BE` или `FE`, без уточнения проекта: проект стоит отдельным сегментом после номера релиза.
- `PI` — Program Increment, например `PI8`.
- `Sprint` — номер спринта внутри PI, например `S5`.
- `Release` — `R1` (mid-sprint) или `R2` (end-of-sprint). Каденция — 2 релиза на прод за спринт.
- `Краткое описание` — суть релиза, 3–10 слов, без канцеляризма (см. общие правила в [gtp-conventions.md](../shared/gtp-conventions.md)).

Примеры:
- `[Revenue/BE]: PI8 S3 R1 — Бэкофис и клиент управления внешними турнирами`
- `[Revenue/FE]: PI8 S3 R2 — Админка — Бэкофис и клиент управления внешними турнирами`
- `[Revenue/FE]: PI8 S5 R1 — casino-web (клиент) — Новый UI бонусного кабинета`

## Хотфиксы

```
[Revenue/BE]: <PI> <Sprint> <Release>-hotfix.<K> — <Описание>
[Revenue/FE]: <PI> <Sprint> <Release>-hotfix.<K> — <Проект> — <Описание>
```

`K` — порядковый номер хотфикса к конкретному релизу (`R1` или `R2`), начиная с 1.

### Хотфикс к хотфиксу

Если после `R2-hotfix.1` нужен ещё один хотфикс к тому же релизу — нумерация продолжается: `R2-hotfix.2`, `R2-hotfix.3` и т.д. Не начинать нумерацию заново и не создавать вложенные обозначения вида `hotfix.1.1`.

Пример последовательности для одного релиза:
1. `[Revenue/BE]: PI8 S5 R2 — Оптимизация gamer-score`
2. `[Revenue/BE]: PI8 S5 R2-hotfix.1 — Фикс 500-ок в exchange-rate`
3. `[Revenue/BE]: PI8 S5 R2-hotfix.2 — Фикс повторного списания баланса`

## Несколько стеков в один день

Это разные Version, даже если деплоятся в одну дату и относятся к одной фиче. Не объединять в одно имя/описание.

- `[Revenue/BE]: PI8 S5 R1 — Бонусная система`
- `[Revenue/FE]: PI8 S5 R1 — casino-web (клиент) — Новый UI бонусного кабинета`
- `[Revenue/FE]: PI8 S5 R1 — Админка — Управление бонусными правилами`

BE, FE-админка и FE-casino-web — три независимых стека. Любая комбинация из них в один день — отдельные Version для каждого.

## Бренды

Отдельного Version на бренд не бывает: имя версии брендом не размечается. Порядок выкатки по продам (обычно сначала Banger, затем Glory и Divine) — это не часть имени.

- Для **BE**-релиза бренд не спрашивать и в выводе не указывать.
- Для **FE**-релиза спросить, на какой прод катим первым, и указать это только в Deployment Info (`**Первый прод:**`). Если пользователь не ответил — `Banger` с пометкой `**Assumption:** первый прод — Banger`.

## Сброс нумерации R1/R2

Нумерация `R1`/`R2` привязана к спринту, а не к календарному месяцу или PI целиком. При переходе на новый спринт нумерация начинается заново:

- `PI8 S5 R1`, `PI8 S5 R2` — релизы спринта 5.
- `PI8 S6 R1`, `PI8 S6 R2` — релизы спринта 6, нумерация не продолжает предыдущий спринт.

Не путать номер релиза в спринте (`R1`/`R2`) с порядковым номером хотфикса (`hotfix.<K>`) — это независимые счётчики.
